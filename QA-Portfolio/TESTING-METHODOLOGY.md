# Testing Approach

During my internship at WebAlive I followed a structured approach to QA testing:

1. **Understand the feature requirements** by reading user stories, product docs and acceptance criteria.
2. **Map user workflows** and identify the critical paths a real customer would take.
3. **Design positive and negative test cases** for each workflow, including edge cases and error handling.
4. **Execute tests** in staging and UAT environments, simulating real-world usage.
5. **Document results and log defects** with clear reproduction steps, screenshots and expected vs. actual behaviour.
6. **Prioritize issues and collaborate with developers** to fix them, clarifying requirements when needed.
7. **Retest fixes and run regression checks** to ensure new changes didn’t break existing functionality.

This approach helped me validate that each module worked from a user perspective and catch any regressions early.
